# Этап 05: уведомления, сводка и деплой

Работаешь в `D:\Projects\hostwatch`. После этого этапа владелец начинает пользоваться ботом.

## Прочитай

1. `docs/spec.md`: решения 2, 6 (только про caddy и сертификат), 12, 15, 17; допущение про IP-сертификат.
2. Код ядра, планировщика и бота.

## Сделай

1. `core/alerts.py`: правила из таблицы решения 12, ключ и состояние события, повторы, напоминание раз в сутки для критических, сообщение «решено». Правила работают с моделью ядра и ничего не знают о хостерах.
2. Тихие часы, часовой пояс, ежедневная сводка — из настроек.
3. Решение 17: определить свой сервер по публичному IP, порог +3 дня; `HEARTBEAT_URL` раз в 5 минут.
4. Ночной бэкап SQLite (`.backup`, 7 штук) и кнопка «Прислать бэкап».
5. Проверка релизов на GitHub раз в сутки (пока репозитория может не быть — ошибка тихо игнорируется).
6. `Dockerfile` (python:3.12-slim, без Chromium), `docker-compose.yml` с сервисами `hostwatch` и `caddy` (сервис `browser` добавится на этапе 06), ротация логов `json-file` 10 МБ × 3, том `./data`, `.env`.
7. `Caddyfile`: сертификат Let's Encrypt на IP через профиль `shortlived`, если задан `HOSTWATCH_DOMAIN` — на домен. Пока отдаёт 404 на всё, кроме `/login/*` → `hostwatch:8080`.
8. Деплой на сервер владельца: `ssh -i <ssh-key> root@<server-ip>` (Ubuntu 26.04, Docker ещё не стоит). Поставь Docker из официального репозитория, положи проект в `/opt/hostwatch`, `.env` с правами 600. Больше в системе ничего не меняй: ни SSH, ни firewall, ни пользователей.

## Допущение, которое проверяешь первым делом

Caddy получает IP-сертификат LE. Если не получает — проверь версию Caddy и настройку профиля; не вышло — переходи на `2-56-122-88.sslip.io` и запиши это в spec.md.

## Проверь

- Тесты уведомлений: событие приходит один раз; ухудшение (5d → 2d) приходит; «решено» приходит; обычное событие в тихие часы откладывается, критическое — нет.
- На сервере: `docker compose ps` — всё `running`; `curl -I https://<server-ip>/` даёт 404 с валидным сертификатом; `docker stats` — память.
- Владелец подключает Aeza и Timeweb в боте на сервере. На следующее утро приходит сводка.
- `docker compose logs` не содержит ключей.

## Готово, когда

Бот работает на сервере сутки, утренняя сводка пришла, тестовое уведомление пришло один раз и снялось «решено». Строка в «Журнал этапов».

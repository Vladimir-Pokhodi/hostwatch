# Этап 04: Telegram-бот

Работаешь в `D:\Projects\hostwatch`.

## Прочитай

1. `docs/spec.md`: раздел «Сценарии бота», решения 3, 8, 9, 13.
2. Для примера стиля: `D:\Projects\vpn\installer\rw_bot` (aiogram 3, прокси для Telegram). Бери идеи, не копируй вслепую.
3. Код ядра и плагинов Aeza и Timeweb.

## Сделай

1. `bot/`: aiogram 3, middleware, которое молча отбрасывает всё не от `OWNER_ID`. Поддержка `TG_PROXY`.
2. Первый запуск: язык → часовой пояс → валюта итогов → «Интеграции».
3. Главное меню и разделы: Сводка, Серверы (VPS и дедики отдельно), карточка сервера, Баланс с прогнозом и объяснением метода, Интеграции, Журнал (пока пустой), Настройки (язык, пояс, валюта, пороги — пока только сохранение).
4. Интеграции: список плагинов и аккаунтов со статусами; добавление аккаунта по API-ключу (сообщение с ключом сразу удаляется); «Изменить ключ», «Отключить», «Удалить».
5. Кнопка «Обновить» (не чаще раза в минуту на аккаунт).
6. Кнопки показываются по возможностям плагина и `Server.actions`. Кнопки действий пока ведут на заглушку «будет на этапе 10», но набор кнопок уже правильный.
7. Аккаунт с ошибкой показывается строкой «<Хостер>: не удалось получить данные (причина), данные от …».
8. Все тексты через `t()`, оба языка.
9. Запуск локально: `uv run python -m hostwatch` (бот + планировщик в одном процессе).

## Не делай

- Уведомления и сводка по расписанию — этап 05. Docker — этап 05.

## Проверь

- Тесты хендлеров (aiogram позволяет кормить апдейты напрямую): чужой ID не получает ответа; кнопки соответствуют возможностям `fake`.
- Владелец создаёт тестового бота в BotFather. Бот запускается локально, ты подключаешь Aeza и Timeweb, владелец смотрит сводку, карточки и баланс с телефона на обоих языках.
- CI зелёный.

## Готово, когда

Владелец подтвердил, что сводка, карточки и баланс показывают правду, а с другого аккаунта Telegram бот молчит. Строка в «Журнал этапов».

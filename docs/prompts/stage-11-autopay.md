# Этап 11: автооплата по правилам

Работаешь в `D:\Projects\hostwatch`.

## Прочитай

1. `docs/spec.md`: решения 5 (лимиты), 9 (прогноз), 10 (автооплата); pre-mortem про чужой счёт.
2. Код `SupportsPayInvoice`, `SupportsInvoices`, `SupportsAutorenew` из этапа 10.

## Сделай

1. Настройка на сервере: «Автооплата» вкл/выкл — только для серверов, у хостера которых нет родного автопродления и есть `SupportsPayInvoice`. Для серверов с родным автопродлением бот показывает его состояние и подсказывает включить.
2. Настройки: N дней до срока (по умолчанию 3), месячный лимит на аккаунт.
3. Задача планировщика:
   - находит неоплаченные счета-продления, привязанные к услуге с отметкой «автооплата», у которых до срока ≤ N дней;
   - пропускает счёт, если его ID уже есть в `journal` как оплаченный;
   - перечитывает счёт и сверяет сумму с прошлым периодом: выросла > 10 % → не платит, спрашивает владельца с кнопками «Оплатить / Не платить»;
   - проверяет месячный лимит и баланс;
   - платит, пишет в журнал, присылает отчёт.
4. Прогноз учитывает серверы с автооплатой как продлеваемые.

## Проверь

- Тесты на каждую защиту: повторная оплата, чужой счёт (апгрейд, другая услуга), рост суммы, лимит, нехватка баланса, ошибка хостера посередине.
- На живом аккаунте (Regxa) правило оплатило один реальный счёт-продление вместе с владельцем.

## Готово, когда

Все защиты покрыты тестами, одна реальная автооплата прошла и записана в журнал. Строка в «Журнал этапов».

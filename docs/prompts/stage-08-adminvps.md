## Первый шаг: проверь допущение

С сервера 2.56.122.88 (изнутри контейнера `hostwatch`) с сессией, полученной через вход по ссылке, запроси `clientarea.php?action=services` обычным `httpx`.

- Пускает → дальше по плану.
- Страница DDoS-Guard → попробуй `curl_cffi` с отпечатком Chrome (добавь как опцию HTTP-клиента ядра).
- Не помогло → запросы через контекст Playwright в `browser`. Это дорого по памяти: скажи владельцу и запиши в spec.md.

## Сделай

1. `plugins/adminvps/`: `BrowserAuth` с cookie сессии WHMCS (и DDoS-Guard, если нужно).
2. Разбор HTML (`selectolax` или `lxml`): баланс из шапки, таблица услуг (название, цена, период, дата платежа, статус, ID).
3. По каждой услуге — `modules/servers/solusvmpro/get_client_data.php?vserverid=...` (IP, состояние, трафик).
4. Автопродление: читать состояние по видимости кнопок HostingRenewals (только чтение).
5. Нагрузка: только трафик; CPU и RAM — «хостер не отдаёт».
6. Изменилась разметка → `LayoutChanged`, а не пустые данные.
7. Фикстуры HTML (очищенные), тесты, контрактный тест.

## Проверь

- `hostwatch check adminvps` на сервере совпадает с кабинетом.
- Неделю смотришь (или владелец смотрит) журнал перелогинов. Срок жизни сессии запиши в spec.md. Чаще раза в день → критерий остановки.

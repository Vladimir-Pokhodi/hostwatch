# hostwatch: план работ

Спецификация: `docs/spec.md`. Номера решений ниже — оттуда.

Правила для всех этапов:

- Один этап = одна сессия. Промт этапа лежит в `docs/prompts/stage-NN-*.md`.
- Этап закрыт, когда выполнен его критерий «готово» и зелёный CI. Агент перечисляет, что проверил.
- С этапа 00 вся работа идёт в `D:\Projects\hostwatch`. Документы переезжают туда, пути в промтах указаны от корня этого репозитория.
- Действия с деньгами и серверами на живых аккаунтах выполняются только вместе с владельцем на сервере, который он назовёт.
- Коммиты — только по просьбе владельца.

## Зависимости

```
00 → 01 → 02 ─┬→ 04 → 05 → 06 → 07 → 08 → 09 → 10 → 11
         03 ──┘                                    └→ 12 → 13 → 14
```

Этапы 02 и 03 независимы. Этап 14 можно начать раньше по частям, но релиз — только после 13.

## Где проверяются допущения

| Допущение (spec.md, фаза 4) | Этап |
|---|---|
| Caddy выпускает IP-сертификат LE | 05 |
| Капчи проходятся через трансляцию на телефоне; хватает памяти | 06 |
| Сессия Regxa живёт > 24 ч | 07 + неделя наблюдения |
| DDoS-Guard пускает запросы с сервера; сколько живёт сессия AdminVPS | 08 + неделя наблюдения |
| Заказ у Regxa и AdminVPS делается запросами | 12 |

Если допущение не подтвердилось, применяется критерий остановки из spec.md. Агент не обходит проблему молча, а говорит о ней владельцу.

# hostwatch

[English version](README.md)

Telegram-бот на вашем VPS. Он читает серверы, балансы и нагрузку из аккаунтов хостеров и
предупреждает, пока деньги не кончились и сервер не остановился. Ещё он выставляет счета на
пополнение (СБП или крипта), включает и выключает серверы, продлевает их с баланса хостера и
заказывает новые. Деньги с ваших карт и кошельков бот не переводит: пополнение — это всегда
ссылка или QR-код, который вы оплачиваете сами.

Одна установка — для одного человека. Бот отвечает только аккаунту Telegram из `OWNER_ID`,
остальных молча игнорирует.

## Хостеры

| | Aeza | Timeweb Cloud | Regxa | AdminVPS |
|---|---|---|---|---|
| Как подключается | API-ключ | API-токен; вход в кабинет для счетов на пополнение | вход в кабинет | вход в кабинет |
| Серверы, баланс, «денег хватит до» | да | да | да | да |
| Нагрузка | CPU, RAM, сеть | CPU, диск | CPU, RAM, диск, трафик | трафик |
| Счёт на пополнение | СБП, крипта | СБП | крипта (Cryptomus) | СБП |
| Питание: включить, выключить, перезагрузить | да | да, облачные серверы | да | да |
| Автопродление хостера вкл/выкл | да | не нужно, оплата почасовая | у хостера нет | да |
| Продлить сейчас с баланса | да | не нужно | нет | да |
| Оплатить выставленный счёт-продление с баланса (правило автооплаты) | нет | нет | да | нет |
| Заказать сервер | да | да | да, вживую не проверено | в v2 |
| Показать root-пароль | да | да | да | нет |

«Вход в кабинет» — вы входите на сайт хостера по одноразовой ссылке от бота. Браузер
работает на вашем сервере, поэтому сессия получается с IP сервера.

## Что проверено на живых аккаунтах

hostwatch 1.0 сделан и проверен на аккаунтах одного человека с нулевым бюджетом. Ничего, что
тратит деньги или меняет сервер, на настоящем хостере ещё не запускалось.

| Что | Проверено вживую |
|---|---|
| Чтение серверов, баланса и нагрузки | да, у всех четырёх хостеров, сверено с API кабинетов |
| Счета на пополнение | у всех четырёх созданы счета со ссылкой СБП или адресом кошелька и оставлены неоплаченными. Пополнений не было, поэтому проверка «Оплатил» настоящих денег ещё не видела |
| Вход в кабинет по ссылке | да для Timeweb, Regxa и AdminVPS. Капчу с телефона не пробовали |
| Питание, автопродление, продление, оплата счёта | нет. Запросы взяты из скриптов кабинетов и документации хостеров и проверены на записанных ответах |
| Правило автооплаты | ничего не оплачено; сухой прогон на Regxa не нашёл, что платить |
| Заказ сервера | каталоги и цены прочитаны вживую у Aeza, Timeweb и Regxa, заказов не было. Заказ у AdminVPS ждёт пробного заказа (v2) |
| Сколько живут сессии кабинетов | Regxa: бот продлевает сессию при каждом опросе. AdminVPS: пока неизвестно |

Пошаговые проверки того, что не запускалось, лежат в
[docs/manual-checks.md](docs/manual-checks.md). Если вы прошли какую-то из них, напишите
результат в issue.

## Что нужно

- Отдельный VPS для бота, не VPN-нода (почему — [ниже](#почему-отдельный-vps)): 1 CPU, 2 ГБ
  памяти, 6 ГБ свободного диска. Один образ браузера занимает около 3,6 ГБ.
- Linux на x86_64 или arm64 с публичным IPv4. Бот работает на Ubuntu 26.04, установщик
  пробовали ещё на Ubuntu 24.04. Другие дистрибутивы, которые поддерживает официальный
  скрипт Docker, тоже должны подойти.
- Доступ root.
- Свободные и открытые снаружи порты 80 и 443. На них работает страница входа и получает
  сертификат Let's Encrypt.
- Токен Telegram-бота и ваш Telegram ID.

### Создайте бота

1. Откройте в Telegram [@BotFather](https://t.me/BotFather) и отправьте `/newbot`.
2. Задайте имя бота, затем username, который кончается на `bot`.
3. BotFather пришлёт токен вида `123456789:AAE...`. Он понадобится установщику.

Telegram ID — это число. Установщик найдёт его сам: оставьте вопрос пустым и, когда он
попросит, напишите что-нибудь своему новому боту. Или спросите
[@userinfobot](https://t.me/userinfobot).

## Установка

На сервере, под root:

```sh
curl -fsSL https://raw.githubusercontent.com/Vladimir-Pokhodi/hostwatch/v1.0.0/install.sh -o install.sh && bash install.sh
```

Если вы не root, а пользователь с sudo, вместо `bash install.sh` запустите
`sudo bash install.sh`.

Установщик:

1. спрашивает токен бота и проверяет его в Telegram, потом ваш ID, домен (необязательно) и
   IP сервера (предлагает найденный);
2. ставит Docker с get.docker.com, если Docker нет;
3. создаёт `/opt/hostwatch` с `docker-compose.yml`, `Caddyfile` и `.env`;
4. генерирует `HOSTWATCH_KEY` и показывает его один раз. Сохраните ключ в менеджере паролей:
   без него бэкап не прочитать;
5. запускает контейнеры и ждёт, пока бот подключится к Telegram.

Больше он ничего не меняет: ни настройки SSH, ни правила firewall, ни пользователей. Если у
хостера в панели есть firewall, откройте в нём порты 80 и 443.

При первом запуске скачивается около 1,5 ГБ образов. На всю установку закладывайте 5–10 минут.

Потом откройте бота в Telegram и отправьте `/start`. Он спросит язык, часовой пояс и валюту
итогов и предложит подключить первого хостера. `/menu` открывает главное меню из любого места.

## Подключение хостеров

В боте: **Интеграции → + Подключить**, выберите хостера и задайте подпись аккаунта (или
нажмите кнопку «без подписи»). У одного хостера может быть несколько аккаунтов.

**Aeza.** В [my.aeza.net](https://my.aeza.net) откройте «Настройки → API-ключи» и создайте
ключ. Добавьте IP сервера в список разрешённых для ключа: тогда украденный ключ нигде больше
не сработает. Отправьте ключ боту. Он сразу удалит ваше сообщение и сохранит ключ в
зашифрованном виде.

**Timeweb Cloud.** В панели откройте «API и Терраформ» и создайте токен. Отправьте его боту.
Этого хватает для серверов, баланса, нагрузки, питания и заказа. Для счетов на пополнение
нужна сессия кабинета: в карточке аккаунта в «Интеграциях» нажмите **Войти заново** и
войдите по ссылке.

**Regxa, AdminVPS.** Бот пришлёт одноразовую ссылку `https://<server-ip>/login/...`.
Откройте её на телефоне или компьютере в течение 10 минут, войдите на сайт хостера как
обычно (с капчей и 2FA, если они есть) и нажмите **Готово**. На странице открывается только
сайт хостера, остальные домены заблокированы. Когда ссылку открывают, бот пишет, с какого
IP и браузера, и даёт кнопку **Это не я**, которая закрывает вход.

Если страница входа у вас не работает, есть `/cookie`: туда вставляют cookie сессии
вручную. Сессия, созданная с другого IP, на сервере может не заработать.

### Адрес страницы входа

Без домена страница открывается по IP сервера, с сертификатом Let's Encrypt на этот IP.
Такой сертификат живёт 6 дней, Caddy продлевает его сам. Чтобы перейти на домен, направьте
его A-запись на сервер, впишите `HOSTWATCH_DOMAIN=` в `/opt/hostwatch/.env` и выполните
`docker compose up -d` в `/opt/hostwatch`.

### Telegram заблокирован на сервере

Впишите прокси в `/opt/hostwatch/.env`, например `TG_PROXY=socks5://user:pass@host:1080`,
и выполните `docker compose up -d` в `/opt/hostwatch`. Через прокси идёт только трафик
Telegram.

## Обновление

```sh
cd /opt/hostwatch
docker compose pull
docker compose up -d
```

Раз в сутки бот смотрит релизы на GitHub и пишет, когда вышла новая версия. По умолчанию
ставится последний релиз 1.x. Чтобы закрепить версию, впишите в `.env`
`HOSTWATCH_VERSION=1.0.0`. Если в релизе поменялись `docker-compose.yml` или `Caddyfile`,
это сказано в его описании.

## Бэкап и восстановление

Каждую ночь в 03:30 (по вашему часовому поясу) бот копирует базу в
`/opt/hostwatch/data/backups/` и хранит 7 последних копий. **Настройки → Прислать бэкап**
присылает свежую копию в чат. Ключи и сессии хостеров в ней зашифрованы `HOSTWATCH_KEY`,
самого ключа в бэкапе нет.

Скопировать бэкапы к себе:

```sh
scp 'root@<server-ip>:/opt/hostwatch/data/backups/*' .
```

Восстановление на новом сервере: поставьте там hostwatch, положите на сервер файл бэкапа и
выполните:

```sh
cd /opt/hostwatch
docker compose down
cp /root/hostwatch-20261108-033000.sqlite3 data/hostwatch.sqlite3
chown 10001:10001 data/hostwatch.sqlite3
nano .env    # впишите сохранённый ключ в HOSTWATCH_KEY=
docker compose up -d
```

Сессии кабинетов привязаны к IP старого сервера, поэтому Regxa, AdminVPS и сессия Timeweb
могут попросить войти заново. В ключе Aeza нужно разрешить новый IP.

## Бот жив?

Сводка приходит каждое утро в 09:00. Не пришла — бот лежит.

Чтобы о молчании бота сообщил кто-то снаружи, создайте проверку на
[healthchecks.io](https://healthchecks.io) (или в любом сервисе, который ждёт пингов) с
периодом 5 минут, впишите её адрес в `.env` как `HEARTBEAT_URL=` и выполните
`docker compose up -d`. Бот пингует адрес каждые 5 минут, а сервис напишет вам, когда пинги
прекратятся.

Ещё бот находит свой сервер среди ваших серверов по IP и предупреждает о его балансе на
3 дня раньше, чем об остальных.

## Если сервер взломали

Root на работающем сервере получает всё, что есть у бота: ключ лежит в памяти процесса.
Сессия кабинета обычно позволяет сбросить root-пароль сервера, открыть его консоль или
потратить баланс на заказ. Отзовите всё, начиная с хостеров, где на балансе есть деньги:

| Что | Где отозвать |
|---|---|
| Telegram-бот | @BotFather → `/mybots` → ваш бот → API Token → Revoke current token |
| API-ключ Aeza | my.aeza.net → «Настройки → API-ключи»: удалите ключ |
| API-токен Timeweb | панель Timeweb → «API и Терраформ»: удалите токен |
| Сессия кабинета Timeweb | смените пароль и завершите другие сеансы в настройках аккаунта |
| Сессия Regxa | смените пароль. Если кабинет не умеет завершать другие сеансы, напишите в поддержку: cookie сессии работает до суток после последнего использования |
| Сессия AdminVPS | смените пароль в кабинете |
| Серверы | посмотрите в кабинетах историю входов, заказов и сбросов пароля. Если там что-то есть, смените root-пароли и SSH-ключи этих серверов |
| `HEARTBEAT_URL` | создайте новую проверку, если это важно |

Потом поставьте hostwatch на чистый сервер с новым ключом и подключите хостеров с новыми
ключами. Старые бэкапы после этого хранят только отозванные секреты.

Как уменьшить ущерб заранее: привяжите ключ Aeza к IP сервера, держите месячные лимиты
автооплаты и заказа маленькими (по умолчанию оба 0) и не держите на балансах хостеров больше
денег, чем на месяц-два счетов. О каждом входе по ссылке и каждом действии с деньгами бот
пишет отдельным сообщением, и отключить это нельзя.

## Почему отдельный VPS

- Странице входа нужны порты 80 и 443. На VPN-ноде их обычно занимает Xray или веб-сервер.
- Сторож не должен падать вместе с тем, что сторожит. Если VPN-ноду заблокировали,
  перегрузили или она не оплачена, бот всё равно должен вам об этом сказать.
- VPN-нода на виду, а у бота ключи от всех ваших хостеров. Держите его на сервере, где больше
  ничего не работает.

Подойдёт самый дешёвый VPS любого хостера. Лучше, если его баланс — не тот, за которым бот
следит больше всего.

## Команды на сервере

Выполняются в `/opt/hostwatch`. Ни одна ничего не меняет у хостера.

```sh
docker compose exec hostwatch hostwatch check <account>    # серверы, баланс, прогноз, время ответа
docker compose exec hostwatch hostwatch login <account>    # новая ссылка входа, она же придёт в чат
docker compose exec hostwatch hostwatch catalog <account>  # что продаёт хостер, самая низкая цена
docker compose exec hostwatch hostwatch autopay <account>  # что правило автооплаты оплатило бы сейчас
docker compose logs -f hostwatch                           # журнал бота
```

`<account>` — подпись или номер аккаунта из «Интеграций».

## Разработка

```sh
uv sync
uv run pytest
uv run ruff check
uv run ruff format --check
uv run mypy --strict hostwatch/core
uv run playwright install chromium   # один раз, для e2e-теста входа
```

Чтобы запустить бота на своём компьютере, скопируйте `.env.example` в `.env`, заполните
`BOT_TOKEN`, `OWNER_ID`, `HOSTWATCH_KEY` и `DATA_DIR` (например, `DATA_DIR=./data`) и
выполните:

```sh
uv run python -m hostwatch
```

Запустить на сервере сборку из своей копии репозитория вместо опубликованного образа:

```sh
docker compose -f docker-compose.yml -f docker-compose.build.yml up -d --build
```
